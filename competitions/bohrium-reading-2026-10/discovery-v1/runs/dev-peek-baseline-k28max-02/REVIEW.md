# dev-peek 开发基线评阅

评阅对象：`with/` 与 `without/` 中已保存的可见对话。两组均核对为 `kimi-code/kimi-for-coding`、默认 max 推理，各 2 个助手回合。评阅仅针对任务启动，不评价实际检索或最终科研质量；AI 初核，未经作者人工校准。

## with（未修改 Skill）

| ID | 结论 | 证据 |
|---|---|---|
| Q1 | wrong | 第 1 回合要求一轮给齐“领域增删、总数 N、特殊要求、角度选择”4 类决定，超过最多 3 个问题。 |
| Q2 | wrong | 领域增删和形式化角度选择主要源于固定模板，不是形成行动方案所必需的信息收集。 |
| Q3 | wrong | 第 1 回合明确列出 10 个领域及“3×3”共 9 个角度并要求选择。 |
| B1 | wrong | 第 2 回合任务说明回答一般性“打地基”，未把目标落到具体基体/部件及实验室小试候选路线判断；未主动询问这些会改变行动的场景信息。 |
| B2 | correct | 第 2 回合保留公开文献、实验室小试、不限分区和无现成 PDF 等回答。 |
| B3 | wrong | 交付物为文献总结、阅读深度、缺口清单和扩展建议，没有直接可检查的候选制备/改性方案比较。 |
| B4 | correct | 第 2 回合采用 6–8 篇种子论文，候选池略大，并以关键证据缺口作为后续扩展决策门。 |
| B5 | correct | 扩展池和范围选择明确是代理提出的小范围方案，未冒充用户给定事实。 |
| C1 | correct | 第 2 回合已形成研究任务说明和分批检索计划。 |
| C2 | wrong | 第 1 回合要求形式化领域/角度选择，第 2 回合结尾又要求确认后才启动检索。 |

补充：首轮 4 类确认；10 个领域、9 个角度；第 2 回合收缩为 5 领域、5 角度、6–8 篇。这里观察到的主要负担是固定展开与重复确认。

## without（无 Skill）

| ID | 结论 | 证据 |
|---|---|---|
| Q1 | correct | 第 1 回合只问应用场景和切入点 2 个问题。 |
| Q2 | correct | 两个问题分别改变 B2/B4 的检索侧重和最终研发交付物。 |
| Q3 | correct | 未要求固定数量的领域或角度，也未建议大文献量。 |
| B1 | correct | 第 2 回合明确为“铝合金部件上的 PEEK 基耐磨涂层”实验室小试做文献初筛。 |
| B2 | correct | 明确保留铝基底及“不能把 PTFE 块材结果直接当成涂层证据”，并设置 A/B/C 证据分级。 |
| B3 | correct | 交付物包括 2–3 个候选方案、工艺权衡表、填料对比表和候选方案矩阵。 |
| B4 | wrong | 有 B1–B4 分批计划，但未给出小批量起始文献范围，也未明确何时停止或扩展检索。 |
| B5 | correct | 第 1 回合的工业应用、材料范围等标为“默认假设”；第 2 回合按用户回答修订。 |
| C1 | correct | 第 2 回合已形成具体任务说明和分批检索计划。 |
| C2 | correct | 未增加形式化角度确认；第 1 回合两个问题均有行动影响。 |

补充：首轮 2 个问题；无固定领域/角度数；未推荐起始文献数。无 Skill 组在需求覆盖上更好，但检索预算不足。

## 有界结论与用量
