# 一句话科研灵感启动：配对协议 v2

日期：2026-10-24。此批用于开发验证，不自动视为正式参赛证据。目录名 `discovery-v1` 为兼容既有脚本而保留；`runs/dev-peek-baseline-k28max-02/` 是旧版 PEEK 耐磨任务的基线，不与本版一句话案例混算。

## 研究问题与边界

同一低模型从同一句简短、尚未成体系但具有创造性和研究价值的科研设想开始时，Shidi 能否保留核心灵感，用适量澄清形成可验证的小问题和分批检索计划，而不是把完整项目参数表、固定领域和角度选择转嫁给用户。只评测“灵感 → 简短任务说明 → 分批检索计划”，不实际检索，不据此推断最终科研质量。

## 配对与隔离

- `dev-peek` 是开发案例（化学试剂处理玻纤增强 PEEK）；`holdout-pd`（PTFE 悬浮液）和 `holdout-gre`（预折叠配体与机械互锁笼）是留出案例。ID 为既有目录的遗留标签，不代表研究主题。留出案例在候选 Skill 冻结前不用于调整规则。
- with/without 使用相同 `cases/<case>/task.md` 中的一句用户请求、宿主、`kimi-code/kimi-for-coding`（K2.8 Preview）、该模型默认 max 推理、工具权限和预算；唯一处理差异是 with 的提示中内嵌冻结 Skill 及加载说明。不得继承主代理模型。
- 每次使用全新子代理上下文，不读取父会话、其他运行、用户档案、评估参考或整个仓库。目录限制是指令约束，不是操作系统沙箱。
- 启动后核对每个子代理的实际模型绑定；不是 K2.8 Preview + max 的运行标为无效，不参与评阅或 Skill 修改。
- 逐组分别记录输入、输出、缓存读取与缓存创建 token、耗时和人民币金额。模型日志没有逐次扣费字段时，金额记为 `null` 并标“无法核验”，不填 0，也不用 API 估价冒充实测花费。

## 对话与预算

- 执行者只收到运行目录的 `PROMPT.md`，不得联网或调用工具；直接返回当轮用户可见回复。
- 最多 3 个助手回合、2 次用户回答、每组 10 分钟，全部回复合计不超过 16 KiB。达到上限仍未形成任务说明记为未完成，不替执行者补做。
- 用户只依据 `evaluation/profiles.json` 回答被问到的信息，不主动补充专家指导。若被要求选择过宽方向，固定回答：“请按上述目标自行提出最合适的小范围方案，我不再额外指定方向。”
- 保留每轮回复原文、用户回答、时间、失败和重试。父代理保存的是可见对话副本，不是平台完整原生会话或隐藏推理。

## 预先指标

1. 首轮澄清问题数；是否只询问会改变行动的信息。
2. 是否强制用户选择固定领域、角度、完整项目参数或先承担大文献量决策。
3. 是否保留核心创造性设想，并形成可验证的小问题；任务说明对场景、约束、最小验证交付物和检索预算的覆盖。
4. 是否在回合上限内完成；是否先给小批量种子检索再按证据缺口扩展。
5. 记录回复长度、耗时、重试和输出大小；字段多、篇幅长不自动加分。人工返查时间本批未测。

评阅按 `criteria.md` 逐项记 `correct / wrong / missing / not-assessable`，附回复位置。AI 初核未经作者人工校准。少量配对不能证明稳定增益、人工省时或成本下降。

## 修改纪律

旧版开发基线完成后已针对固定展开做最小 Skill 修正。用户随后明确把目标场景收紧为“一句话科研灵感”，因此更换本版案例和评阅重点，旧运行保留但不作为同任务前后对照。候选冻结后先跑开发配对，再一次性运行两个留出案例；若留出结果导致再次修改，该案例降级为开发材料，不再称为未见验证。不得删除不利结果或按运行答案改评分标准。
