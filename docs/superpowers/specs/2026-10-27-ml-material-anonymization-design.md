# ML 示例物料角色化设计

## 目的

避免公开 ML 示例、产品首页和当前 Skill 配方模板显示具体物料名称，同时保留合成数据、分组验证、质量分数闭合和演示结果的可复现性。

## 目标

- 配方四类组分统一为：填料 `filler`、添加剂 A `additive_a`、添加剂 B `additive_b`、基体 `matrix`。
- 同步修改 ML 示例的 README、CSV 列名与数据、生成器、建模脚本和先验模板。
- 同步修改根 `README.md`、`README_EN.md`、当前 `skills/shidi` 及其 Pro/Flash 模式下的配方 schema 与模板。
- 具体聚合物、具体填料和其他具体添加剂名称均不再显示；原功能名称也统一为上述角色。
- 保持 120 行数据、数值、随机种子、质量分数闭合和模型结果不变，仅更改角色标签。

## 非目标与反目标

- 不改写原始科研运行、竞赛证据、冻结示例资源或文献报告。
- 不改变模型、依赖、分析逻辑或宣称。
- 不用删除文件或降低可复现性的方式完成模糊化。

## 方案比较

- 选定：按角色命名。保留配方逻辑和可读性，符合用户选择。
- 未选：全部使用物料 A/B/C/D。隐藏程度更高，但会损失角色信息。
- 未选：只删除具体聚合物名称、保留其他功能名称。不能满足“所有物料模糊化”。
- 未选：只修改 ML 目录。公开首页和当前 Skill 模板仍会显示具体名称，已由用户明确排除。

## 实施边界

- 修改 `examples/materials_small_data/` 内全部 6 个跟踪文件。
- 修改两个根 README，以及当前 `skills/shidi`、Pro、Flash 三处相同的配方 schema 和 CSV 模板。
- 添加回归检查，验证公开使用文件无具体物料标签、角色列完整、120 行均为 synthetic、生成器与 CSV 数值一致、质量分数闭合。
- 运行 ML 快速演示、仓库 `validate.py` 和完整单元测试。
- 扫描上述公开使用文件，确认具体物料及原功能标签无残留；冻结竞赛证据不在改写范围内。
- 同步 `main`、`feature/shidi-pro-flash`、`competition-materials` 三个公开分支；每个分支单独提交并保留各自历史。

## 验收

公开使用文本与代码只使用选定角色；示例快速运行通过；原 CSV 数值除列名外不变；完整检查通过后推送对应分支，不合并三个分支彼此的其他差异。
