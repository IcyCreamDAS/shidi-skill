# 评分系统（v2，文献标注用）

**从 2026-10 起使用 v2 七维口径**：新增「数据完备度」维度，下调期刊声望与人脉权重。
**分数由脚本确定性计算**——LLM 只给每个维度的整数分，封顶 / 一票否决 / 总分 / 排序交给
`scripts/score_papers.py`，不再让模型心算。

> v1（六维，主题35/方法20/期刊15/网络10/应用10/归档10）仍可用 `--schema v1` 兼容旧数据，见文末对照。

## 七维定义（v2，满分 100）

| # | 维度 | 权重 | 衡量什么 | JSON key |
|:--|:--|:--:|:--|:--|
| 1 | 主题匹配 | 30 | 与用户研究问题/关键词的贴合度 | `topic` |
| 2 | 方法价值 | 20 | 方法/实验设计/分析技术的质量与可借鉴性 | `method` |
| 3 | **数据完备度** | **15** | 样本量 n / 误差棒或置信区间 / 负样本与失败配方披露 / 正交实验表完整度 / 测试标准与条件是否写全 | `data` |
| 4 | 期刊质量 | 10 | 声望与可信度（对照 `journal-list.md` 识别；不再是主导项） | `journal` |
| 5 | 网络关联 | 5 | 与用户指定作者/机构/合作者的联系（**不是看名头**） | `network` |
| 6 | 应用价值 | 10 | 实用协议、数据、工程启示 | `application` |
| 7 | 归档价值 | 10 | 长期参考价值：综述潜力、经典地位 | `archive` |

**为什么加"数据完备度"**：AI4S 数据挖掘最怕"顶刊只报冠军性能、隐去失败配方"；专业学会期刊
（如 *Macromolecules* / *Polymer* / *Composites Part A*）常给出完整正交表、负样本与误差棒。
把数据完备度纳入排序，才能让"能拿来建模的文献"排在"看起来漂亮的文献"前面。

## 评分流程

1. 按七维给每篇打**整数分**，输出 JSON（id + dimensions）：

   ```json
   [
     {"id": "10.1021/acs.joc.0c01234",
      "dimensions": {"topic": 28, "method": 16, "data": 12, "journal": 8,
                     "network": 0, "application": 7, "archive": 5}}
   ]
   ```

2. 跑脚本，拿确定性结果：

   ```powershell
   python scripts/score_papers.py scores.json                 # JSON 输出
   python scripts/score_papers.py scores.json --format md     # Markdown 表
   python scripts/score_papers.py scores.json --strict        # 超上限直接报错
   python scripts/score_papers.py --schema v1 scores.json     # 旧六维口径
   ```

3. 脚本输出：每篇 `total` / `vetoed` / `rank`，超上限自动封顶并给 warning；
   `topic < 10` 的文献不进 ranking；`--strict` 下任何违规直接非零退出，迫使重打分。

## 评分硬规则（脚本执行）

1. **每维封顶**：单维分不得超过权重（脚本封顶；`--strict` 直接报错）
2. **总分重算**：总分 = 七维之和，由脚本求和，不信任子代理/模型算术
3. **一票否决**：`topic < 10` → 直接淘汰，不参与排序
4. **防虚高**：知名度高的论文不得因"有名"而在主题匹配上虚高——主题分必须落到实际相关度
   （这条脚本判断不了，仍需打分时给出引用证据）

## 评分输出格式（报告里）

每篇输出：标题 / 期刊（🔴高质量 / 领域期刊 / 普通）/ 七维明细与总分（脚本产出）/ 一句理由。
报告里不要手写总分，直接贴脚本结果。

## v1 → v2 对照（2026-10）

| 维度 | v1 权重 | v2 权重 | 变化理由 |
|:--|:--:|:--:|:--|
| 主题匹配 | 35 | 30 | 仍是最重项，略降给数据维度让位 |
| 方法价值 | 20 | 20 | 不变 |
| 数据完备度 | — | **15** | 新增：建模可用性核心 |
| 期刊质量 | 15 | 10 | 顶刊≠数据完整；降为辅助信号 |
| 网络关联 | 10 | 5 | 人脉只作微调，不左右排序 |
| 应用价值 | 10 | 10 | 不变 |
| 归档价值 | 10 | 10 | 不变 |

旧数据用 `--schema v1` 仍可复算；新任务一律 v2。

## 校准

连续执行 2-3 次后与用户复盘评分分布：

- 若 Top 文献普遍 ≥90 → 标准过松，收紧
- 若无文献破 60 → 关键词过窄或领域稀疏，放宽
- 根据用户反馈调维度权重（须同步改 `score_papers.py` 的 `SCHEMAS` 与本文档）

## 数量语义

用户给的 N = **文献总数**。按角度数均分（不足时优先高分角度），并保持每个角度至少 1 篇。
